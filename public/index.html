官方数据来源与对照口径

官方账户数值通过本机官方 Codex App Server 的 account/usage/read 读取，日期保留服务返回值。接口没有说明每日时区；这里默认用 UTC 做对照，也可切换北京时间，切换只重新分组本机记录，不修改官方数值或概览口径。

概览与明细仅纳入明确 GPT 型号，排除已知第三方提供方。对账另列日志明确标记为 OpenAI 的未分类请求，包含 codex-auto-review 等原始别名；原始请求 ID 去重后与 GPT 合并为本机可观察合计，不能据此断言官方账户包含相同范围。来源标记缺失的旧记录仍按型号筛选，不能视为已验证 OpenAI。本机日志的历史账户归属与提供方需要另行核实；官方也未给出每日模型和缓存拆分。两边数值接近或相等仍不证明完整范围一致。

启动时读取官方一次，成功后每小时更新，失败后 15 分钟重试；手动更新间隔至少 5 分钟。每 3 秒刷新只读取本机记录和已保存的官方缓存。历史缓存保留每个日期自身的接口读取时间；读取成功不代表服务统计已完整更新，公开接口没有返回统计截止时间。官方未提供不代表零。对账独立于软件、模型和概览日期筛选，差额不能直接换算成费用或套餐额度。

怎样判断差额

先核对日期边界和日志计数，再确认账户与模型范围。不能只凭差额判定官方漏算或计费异常。

累计值、逐次用量与去重

逐次请求按 response_id 去重；旧格式只推算累计增量，并抵扣同区间已记的原生请求。重复通知不能再累加，缓存输入和推理输出已经包含在总量内。

OpenAI 的累计统计原则 ↗
公开报告说明了什么
  • Profile 日桶与统计更新不一致：多位用户报告；未看到官方确认统一根因，接口读取时间不等于统计截止时间。
  • 每日热力图日期与本地日期不同：用户报告，官方时区尚无明确说明。
  • 当天热力图数值未及时更新：用户报告，不代表历史大差额都可由延迟解释。
  • 第三方统计工具重复累加而多算：说明本机工具也需要审计，不能据此认定官方漏算。

Token 怎样计算

总 Token = 输入 + 输出。输入已经包含缓存读取；输出已经包含推理 Token，二者都不重复加到总量。

缓存命中率 = 缓存读取 ÷ 输入总量。未缓存输入 = 输入 − 缓存读取；若来源有缓存写入，它属于未读取缓存的输入，不代表全部都是普通输入计费。推理、缓存写入明细缺失时保留未知。

按北京时间的自然日归属；今天、近 7 天和近 30 天都包含今天，今天尚未结束。无记录日期表示本机没有计数记录，不证明账户当天完全未使用。

计数记录不等于聊天条数：一次任务可以多次调用模型。旧格式累计值只能推算增量，历史不完整时跳过无法归属的部分。

Codex 账户热力图来自账户服务的每日汇总，本看板只读取本机日志中的明确 GPT 模型；两者尚未完成账户对账。热力图按服务返回的日期展示，本看板按北京时间分组，不能仅凭日期文字直接对比。codex-auto-review 等别名无法确认实际 GPT 版本，不计入概览的 GPT 总量；日志明确标记为 OpenAI 的逐请求原始用量在 Codex 对账中单独列出，不猜测缺失用量。

本机统计只读留存日志；官方账户用量通过官方 Codex 程序读取。看板不读取密钥、不启动对话、不修改代理或登录配置；Token 数不能换算成套餐额度或官方账单。
